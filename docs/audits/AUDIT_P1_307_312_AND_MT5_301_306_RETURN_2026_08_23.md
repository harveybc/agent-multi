## New findings

### AUD-F1-20260823-313 (S3, reproduced)

`outer_endpoint()` reads nonexistent manifest keys `rows` and `sha256`.
The materialized schema uses `scored_rows` and `csv_sha256`. Consequently all
three accepted GPU reports publish `role_rows: null` and `csv_sha256: null`
despite evaluating the real outer split. A result endpoint without bound row
count and content digest is not admissible for the 4x3 decision campaign.

Required correction: consume the actual schema, require positive non-boolean
`scored_rows`, require a 64-hex `csv_sha256`, re-hash the CSV immediately before
evaluation, assert equality, and regression-test missing, malformed,
substituted and post-manifest-mutated outer data. Re-run only the bounded smoke
needed to prove populated evidence; do not repeat completed training if the
selected bundles can be evaluated immutably.

### AUD-SEC-20260823-314 (S3, reproduced by inspection)

`tools/materialize_local_profile.py` checks that the requested name is bare,
but writes with `Path.write_text()` to a potentially pre-existing symlink.
That can follow a link outside `~/.config/lts` and disclose the effective
profile. The tool also does not enforce directory mode 0700 or an atomic,
no-follow installation.

Required correction: refuse symlink/non-regular destinations, enforce the
directory as 0700, create a 0600 temporary file with no-follow/exclusive
semantics, fsync file and directory, atomically replace only a verified local
regular destination, and add adversarial symlink/race/permission tests. Never
print substituted values.
