# 21. OANDA Practice Execution Reality Lab

## 1. Purpose

The optimization stack estimates trading behavior; this track measures the
actual broker contract. It runs in parallel and does not interrupt DOIN. Its
first job is to replace assumptions about instruments, spreads, financing,
precision, order semantics and reconciliation with broker-observed evidence.

OANDA Practice is useful for API and execution-process calibration. It is not
treated as proof of live-market liquidity or future profit.

## 2. Implemented Boundary

Repository `lts` owns:

- a Practice-only REST client;
- account/instrument/price preflight;
- restart-safe account, quote and transaction observation;
- local SQLite OLAP facts and analytical views;
- protected market canaries;
- a CLI, tracked config, systemd example and operator runbook.

The client accepts only `https://api-fxpractice.oanda.com`. Credentials are
read from environment-variable names in the config. Raw account IDs and tokens
are excluded from persisted facts.

No normal order path may submit a risk-increasing order without both SL and TP.
The canary additionally requires `orders.enabled=true` in a local config and an
exact command-line confirmation.

## 3. Asset Selection

Selection is generated by:

```text
financial-data/_scripts/analysis/select_oanda_practice_assets.py
```

Evidence sources:

1. validation-only E4 asset-policy results: three seeds and approximately
   49 weeks for model quality, seed stability and exact artifact identity;
2. the comparable annual-diversity validation survey for an activity proxy;
3. explicit portfolio/control roles.

The observation-priority score allocates live-calibration attention. It does
not merge unlike protocols into a financial winner score.

Initial universe:

| Instrument | Role | Why it is present |
| --- | --- | --- |
| `EUR_USD` | execution control | liquid broker/API control independent of alpha |
| `USD_CAD` 4h | long-horizon alpha shadow | best mean E4 annual validation RAP among the tested FX assets |
| `NZD_USD` 1h | short-horizon alpha shadow | second-best mean E4 annual validation RAP among the tested FX assets |
| `GBP_JPY` 1h | activity/diversification shadow | materially higher historical decisions per week |
| `USD_JPY` 1h | activity alternate | second high-activity E4 FX path |
| `EUR_JPY` 4h | historical comparator | positive comparable historical validation evidence |

OANDA account discovery is authoritative. Unsupported instruments fail closed
and require an explicit manifest revision.

## 4. Phase Sequence

### 4.1 Preflight

- authenticate to Practice;
- fetch account and instruments;
- record precision, pip location, minimum size and margin rate;
- fetch a quote for each available selected instrument;
- establish the transaction cursor.

No order permission exists.

### 4.2 Day 1: read-only

Run 24 hours and measure:

- capability coverage;
- quote observation coverage;
- p50/p95 spread in basis points;
- API/session failure rate;
- transaction cursor and deduplication health;
- account-state continuity.

This phase validates plumbing and costs, not profit.

### 4.3 Protected canaries

After manual review, submit minimum-size buy and sell canaries during liquid
hours. Both SL and TP are attached atomically. Acceptance requires:

- broker acknowledgement;
- attached protection;
- no unexplained order/trade/position difference;
- no duplicate after restart;
- persisted intent and execution report.

Any failure blocks portfolio shadow execution.

### 4.4 Week 1: portfolio shadow

Run the selected artifact set for seven days. Model decisions remain shadow
until protected canaries pass. Record:

- intended versus broker-compatible action;
- implementation shortfall;
- spread, commission, financing and conversion drag;
- rejection, cancellation and protection status;
- execution-adjusted weekly return and RAP;
- model/simulator versus Practice metric drift.

One week is descriptive execution evidence. Promotion still requires the
declared longer validation and Practice gates.

## 5. Metric Policy

Day-one readiness is a vector, not profit:

```text
availability + coverage + spread distribution + errors + reconciliation
```

Week-one financial comparison uses the same explicit units as Project3:

- mean weekly return: fraction/week and percent/week;
- annual return: only with declared extrapolation/coverage;
- mean weekly RAP: fraction/week and percent/week;
- annual RAP: only with declared extrapolation/coverage;
- drawdown, costs, trade count and observed duration.

No day result receives an annual label. No dimensionless readiness or optimizer
score is formatted as return.

## 6. OLAP and Lineage

Default local database:

```text
~/.local/state/lts/oanda-practice-lab.sqlite
```

The selection manifest stores exact E4 job IDs. The Practice OLAP stores the
config hash, account fingerprint, session IDs, broker times, transaction IDs
and raw redacted response evidence. This permits later Metabase ingestion and
comparison to simulation without retaining secrets.
